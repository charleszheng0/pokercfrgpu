# Research notes

These original papers guide the CPU reference, experiments, and future work. The published poker systems are **not reproduced**. The table distinguishes ideas implemented in this restricted project from ideas still absent.

| Source | Core contribution and relevant location | Used here | Departure / pending work |

At a CFR information set `I`, the regret increment for action `a` uses opponent and chance reach `π₋ᵢ(I) π_c(I) [vᵢ(I,a) − vᵢ(I)]`; average strategy weight uses the acting player's reach `πᵢ(I)`. The postflop CPU tree now multiplies the private-deal probability by each blocker-aware public-card reveal probability before accumulating child regrets and average strategy. Tests check turn/flop reveal normalization and river numerical parity; wider information-set grouping and convergence suites remain necessary.

The new [Kuhn reference](../small_games/kuhn_reference.py) and Leduc `SynchronousCFR` apply this reach weighting with strategies frozen for each complete deal sweep. Kuhn's first-player equilibrium value is −1/18 under the one-chip ante and one-chip bet rules; an [academic treatment](https://poker.cs.ualberta.ca/publications/bard.msc.pdf) records that value. Exact best responses enumerate pure information-set policies in Kuhn and group hidden deals at the same information set in Leduc. Measured NashConv falls as CFR iterates.

The river prototype applies the same idea to a tiny explicit weighted range over real 52-card hands. In each information set the solver groups all compatible opponent hands sharing the acting player's private hand and public action history. Its hand-dependent label is currently a **conditional root EV** under the average river policy. With the generated disjoint ranges and normalized independent weights, this coincides with a root counterfactual value up to chance normalization; with card collisions or nonuniform own-hand reach, that distinction matters. The model is not trained on public betting states and has not been used at depth cutoffs. DeepStack-style opponent counterfactual-value constraints are absent, so no safe re-solving guarantee is claimed.

The [NFSP paper's Algorithm 1 and Section 4.1](https://arxiv.org/pdf/1603.01121) motivated the separate Q and average-policy networks, reservoir, and anticipatory mode. The original Leduc experiment used a one-layer 64-unit network, SGD, larger memories, target updates every 300 updates, η=0.1, and decaying exploration. This project currently uses two 128-unit layers, Adam at 0.001, 10,000-entry memories, target updates every 200 updates, and fixed ε=0.1. Its custom Leduc rules also differ. We experimentally changed only η from 0.1 to 0.3 at 20,000 episodes and observed lower NashConv in three seeds; this is a local result, not a reproduction of the paper's reported equilibrium quality.

The separate 20-chip Hold'em NFSP path uses an 11-slot masked action abstraction, two 128-unit layers, Adam at 0.001, 100,000-entry replay and reservoir capacities, η=0.3, fixed ε=0.1, and 10,000 self-play hands per seed. Its observed return improved versus an initialized policy against random play across three seeds, but it lost chips to the heuristic. This establishes a working self-play learner under these rules, not an approximate Nash equilibrium. The local river CFR strategy is not a teacher for this NFSP network, and neither shares a value model.

### River update variants and what is implemented

The [CFR+ paper by Tammelin (2014)](https://arxiv.org/abs/1407.5042) motivates clipping cumulative regret at zero and weighted strategy averaging. This code applies `R⁺ ← max(0, R + ΔR)` and weights average-strategy accumulation by iteration. The implementation traverses both players synchronously from a frozen per-information-set strategy. It does not reproduce every CFR+ engineering detail, alternating updates, pruning, or compression, so results are described as this synchronous CFR+ variant.

[Discounted CFR by Brown and Sandholm (2019)](https://arxiv.org/abs/1809.04040) motivates the DCFR discounts. Before iteration `t`'s regret increments, positive cumulative regrets are multiplied by `t^α/(t^α+1)` and nonpositive regrets by `t^β/(t^β+1)`; accumulated average strategy is discounted by `(t/(t+1))^γ`. The experiment uses α=1.5, β=0, γ=2. It does not implement the paper's other variants, sampling, or pruning.

[Deep CFR (Brown et al., 2019)](https://arxiv.org/abs/1811.00164) is relevant to a later neural alternative: it approximates CFR advantage/strategy information with networks and memories. The current solver remains tabular and exact over its tiny explicit deal set; the failed root-EV network is not used for CFR updates or continuation values.

[Kim (2024), GPU-Accelerated CFR](https://arxiv.org/abs/2408.14778) reframes CFR computation as dense/sparse matrix and vector operations to exploit parallel hardware, with memory use as a tradeoff. This supports a future flat-array CPU representation and profiling plan, but no CUDA implementation or claimed speedup exists. The 2024 paper is the cited GPU source; later papers are outside the present implementation scope.

For every information set `I` and action `a`, the solver accumulates the counterfactual regret increment
`ΔRᵢ(I,a) = Σ_{h∈I} π_c(h) π_{-i}(h) [vᵢ(h,a) − vᵢ(h)]`.
The traversal's `chance` factor starts with the normalized probability of a compatible pair of private hands and multiplies exact public-card reveal probabilities at chance nodes; `reach[other]` is opponent action reach. Strategy averaging instead weights by `π_c(h) πᵢ(h)`. CFR counterfactual values remain unnormalized by the acting hand's own chance probability. The analysis layer separately computes ordinary conditional action EV by normalizing over compatible opponent hands given the acting hand and then evaluating terminal chip utility under a forced root action plus the average continuation profile. Thus the reported action EV is not copied from a regret accumulator.

The [river benchmark](../experiments/river_variants.py) compares the three updates on the same 9-compatible-deal river abstraction. The newer [shared solver benchmark](../experiments/shared_solver_milestone.py) compares the chance-aware solver with that preserved river reference and evaluates all three updates on one exact turn-to-river game. The river policies and EVs matched exactly on the four-deal fixture; on the one-deal 100-iteration turn fixture, DCFR had the lowest restricted-game NashConv, but that isolated result is too narrow to select a default for other positions. Exact flop search with one deal and one iteration remained slow and far from convergence. These checks do not establish a full Hold'em equilibrium, safe continual re-solving, or accurate human betting-history ranges.

### Chance sampling and exact all-in integration

Lanctot, Waugh, and Bowling's [Monte Carlo Sampling for Regret Minimization in Extensive Games](https://webdocs.cs.ualberta.ca/~bowling/papers/09colt-ws.pdf), Section 3 and Equation 6, motivates replacing a full chance expectation in a CFR update with a sampled estimator whose expectation equals the exact counterfactual value. The research code samples public turn/river outcomes from their true blocker-aware chance probabilities, enumerates private deals, and leaves all player actions in the traversal. Because the sampled outcome is drawn from the actual chance distribution, its branch value is not multiplied by that outcome probability again; the initial joint-deal mass remains in the counterfactual reach. It uses vanilla CFR only. A fixed one-step turn experiment across 500 seeds found mean root regret within 0.01 chips of the exact update, and seeded replay is deterministic. This narrow test does not establish the full paper's regret bound for this implementation.

All-in nodes have no remaining player decisions. Their expected payoff is integrated exactly by unordered card combinations, a deterministic variance reduction step that also avoids repeated tree construction. Caching seven-card scores by canonical board and private hand removes repeated evaluation across betting histories. The saved [multi-street comparison](../experiments/multistreet_scale.json) shows a large runtime reduction but sampled strategies remained substantially more vulnerable than deeper exact profiles on both fixed positions. The app therefore continues using exact restricted solves only, and automatic full-hand advice remains gated.
