# Architecture

The new CPU reference is independent of the historical research scripts. `cards.py` scores every five-card subset of a five-to-seven-card hand into category and lexicographic kickers. `engine.py` deals and burns from a seeded deck, tracks street/total contributions and stacks, posts short blinds, supports preset agent targets plus arbitrary legal integer-chip targets, and emits observations. `is_legal_action()` validates min-raises, effective-stack caps, and short all-ins; short all-ins do not reopen raising. The event history records blinds, actions, board reveals, uncalled returns, and awards. Heads-up play has no contested side pot: effective-stack caps and uncalled-chip refunds handle the only excess-contribution case. Tied odd chips go to the first seat left of the button.

`agents.py` consumes only observations. The random agent selects a legal action. The heuristic agent estimates random-opponent showdown equity with Monte Carlo sampling, then applies simple thresholds. `play.py` gives seat 0 to a human and seat 1 to either baseline. `experiments/baseline.py` plays reproducible hands with seat rotation and writes JSON.

`small_games/train_nfsp.py` contains distinct Q and average-policy networks, replay and reservoir buffers, and episodic anticipatory mode. `small_games/compare_cfr_nfsp.py` contains a separate Leduc CFR implementation and a policy comparison path. They are not wired to the new Hold'em engine. Original weights are in `artifacts/legacy/`; new training writes to `artifacts/nfsp/`. The historical CUDA files in `cuda_experiments/` are outside the CPU reference and have not been benchmarked here. `examples/template_tensor.py` is a standalone learning exercise.

`small_games/kuhn_reference.py` implements full-tree synchronous CFR and exact pure-policy enumeration for best responses. `small_games/compare_cfr_nfsp.py` now also offers `SynchronousCFR`, which freezes the strategy over the complete physical-deal sweep before applying regret increments. The original incremental `CFR` class remains available for comparison.

`poker_cpu/nfsp.py` is a separate full-hand restricted Hold'em NFSP learner. Its 525-float observation encodes only the acting player's cards, public board, position, stacks, pot, contributions, public betting history, and legal action amounts/mask. Eleven fixed action slots map to fold/check/call and up to four bet or raise targets. A DQN and target network estimate approximate best response; a separate network learns the reservoir-sampled average policy. Each agent selects its anticipatory mode once per hand. Replay transitions carry legal masks, and terminal rewards are divided by the 20-chip starting stack for Q training. `experiments/holdem_nfsp.py` trains and saves per-seat policies and Q networks; fixed-opponent evaluators use the saved seat-0 average policy. This network is not shared with the river CFR solver or Leduc NFSP.

`trainer/server.py` serves a local JSON API and browser page. A per-browser session owns one `HoldemGame` and one opponent agent. The table shows both players' street contributions, stack, blind/button role, board, legal preset actions, and a custom target control accepting any server-validated legal integer wager. Completed hands preserve actions, board, rewards, and holes only when showdown made them public; folded opponent cards stay hidden. In matched 20-chip NFSP games, the separate seat-0 policy supplies action probabilities and inference time; these are clearly labeled experimental model probabilities, not equilibrium frequencies. Custom human wagers are marked outside the NFSP action set. Per-action EV remains unavailable because no validated full-hand solver produces those values. The dashboard reads saved experiment JSON files, so it cannot invent curves or strength metrics. No Leduc policy is presented as a Hold'em opponent.

`poker_cpu/solver_interface.py` defines a future `SolverRequest`/`SolverAnalysis` boundary carrying public state, acting player, ranges, legal action abstraction, stacks, pot, history, and time budget. Its placeholder backend reports `unsupported` and leaves action frequencies, action EVs, EV loss, iterations, latency, and convergence absent. It is not called as if it were a solver.

`poker_cpu/river_solver.py` is a separate local research model for a complete five-card board. Input: public board, starting pot/effective stack, up to a small explicit list of private hands per seat, and optional range weights. `WeightedRange` validates and normalizes explicit beliefs, removes public/known-card blockers, and applies per-hand action likelihoods; `RiverGame` removes mutual hand collisions and renormalizes joint deals. Its state stores public betting history and per-seat river contributions; each information set adds only the acting player's hand. Synchronous CFR weights regret by opponent/chance reach and average strategy by own/chance reach. Exact best response groups compatible hidden deals by information set. Its output is a local average policy, NashConv, and per-hand conditional root EV. The tree permits min/half-pot/pot/all-in targets and one raise. Weighted range conditioning is groundwork only; turn/flop chance, betting-history range inference, and safe re-solving are not implemented.

`experiments/river_value.py` samples distinct boards and private ranges, solves each river game more deeply, and records a per-hand conditional root EV label. The base network input is a 425-float vector: board and own-hand card indicators, three weighted hand slots for each range, seat, pot, and stack. One experiment appends exact showdown equity, producing 426 inputs. Output is one scalar root EV per own hand. This is not a continuation-value network: it lacks a non-root public betting state and opponent counterfactual-value constraints, so it is not usable as a depth-cutoff oracle or live action adviser. The label audit and suit-augmentation experiment are in `experiments/diagnose_river_value.py`; current measurements are in `docs/BENCHMARKS.md`.

The Hold'em NFSP model was trained using this same engine, 20-chip stacks, 1/2 blinds, the same 525-float observation encoder, restricted preset action mapping, and net-chip rewards divided by 20. It is an experimental policy for that environment; arbitrary human wagers can create observations outside its training distribution. It is separate from Kuhn/Leduc NFSP and from CFR. The river CFR boundary is public river state plus explicit private ranges → local average policy and conditional per-hand root values. A true continuation model `(public position, both ranges, hand)` → counterfactual value vector, turn/flop chance traversal, depth-cutoff integration, and safe continual re-solving remain planned. CPU output is the correctness reference for later acceleration.
