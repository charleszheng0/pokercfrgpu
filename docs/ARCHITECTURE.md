# Architecture

`trainer/offline_training.py` runs NFSP in a separate low-priority, single-Torch-thread CPU process. Starting the trainer server starts its scheduled worker unless `--no-training` is passed; the ML Training tab can save validated settings, start, stop, and poll status. Each cycle writes atomic JSON progress/history, local PyTorch checkpoints including optimizer/replay/RNG state, and per-seat policy weights. A run evaluates the same seat-1 policy used by the app and promotes it only after the configured fixed-opponent gate passes. The server reads `active.json` only when creating a new NFSP hand, so ongoing hands retain their loaded policy. The worker also re-solves one fixed explicit-range river demo at the configured CFR+ iteration budget; it stores/promotes only a lower-NashConv result under a fixed 0.1-chip gate. `trainer/solution_cache.py` keys solved responses by the complete demo request and solver-source fingerprint and samples actions only from a saved matching strategy. This local cache is not a preflop or multi-street blueprint. The random legal-action bot is preserved as an experimental baseline, separate from cached strategy sampling. No neural continuation model or CUDA path is active.

The new CPU reference is independent of the historical research scripts. `cards.py` scores every five-card subset of a five-to-seven-card hand into category and lexicographic kickers. `engine.py` deals and burns from a seeded deck, tracks street/total contributions and stacks, posts short blinds, supports preset agent targets plus arbitrary legal integer-chip targets, and emits observations. `is_legal_action()` validates min-raises, effective-stack caps, and short all-ins; short all-ins do not reopen raising. The event history records blinds, actions, board reveals, uncalled returns, and awards. Heads-up play has no contested side pot: effective-stack caps and uncalled-chip refunds handle the only excess-contribution case. Tied odd chips go to the first seat left of the button.

`agents.py` consumes only observations. The random agent selects a legal action. The heuristic agent estimates random-opponent showdown equity with Monte Carlo sampling, then applies simple thresholds. `play.py` gives seat 0 to a human and seat 1 to either baseline. `experiments/baseline.py` plays reproducible hands with seat rotation and writes JSON.

`small_games/train_nfsp.py` contains distinct Q and average-policy networks, replay and reservoir buffers, and episodic anticipatory mode. `small_games/compare_cfr_nfsp.py` contains a separate Leduc CFR implementation and a policy comparison path. They are not wired to the new Hold'em engine. Original weights are in `artifacts/legacy/`; new training writes to `artifacts/nfsp/`. The historical CUDA files in `cuda_experiments/` are outside the CPU reference and have not been benchmarked here. `examples/template_tensor.py` is a standalone learning exercise.

`small_games/kuhn_reference.py` implements full-tree synchronous CFR and exact pure-policy enumeration for best responses. `small_games/compare_cfr_nfsp.py` now also offers `SynchronousCFR`, which freezes the strategy over the complete physical-deal sweep before applying regret increments. The original incremental `CFR` class remains available for comparison.

`poker_cpu/nfsp.py` is a separate full-hand restricted Hold'em NFSP learner. Its 525-float observation encodes only the acting player's cards, public board, position, stacks, pot, contributions, public betting history, and legal action amounts/mask. Eleven fixed action slots map to fold/check/call and up to four bet or raise targets. A DQN and target network estimate approximate best response; a separate network learns the reservoir-sampled average policy. Each agent selects its anticipatory mode once per hand. Replay transitions carry legal masks, and terminal rewards are divided by the 20-chip starting stack for Q training. `experiments/holdem_nfsp.py` trains and saves per-seat policies and Q networks; fixed-opponent evaluators use the saved seat-0 average policy. This network is not shared with the river CFR solver or Leduc NFSP.

`trainer/server.py` serves a local JSON API and browser page. A per-browser session owns one `HoldemGame` and one opponent agent. The table shows both players' street contributions, stack, blind/button role, board, legal preset actions, and a custom target control accepting any server-validated legal integer wager. Completed hands preserve actions, board, rewards, and holes only when showdown made them public; folded opponent cards stay hidden. In matched 20-chip NFSP games, the separate seat-0 policy supplies action probabilities and inference time; these are clearly labeled experimental model probabilities, not equilibrium frequencies. Custom human wagers are marked outside the NFSP action set. Per-action EV remains unavailable because no validated full-hand solver produces those values. The dashboard reads saved experiment JSON files, so it cannot invent curves or strength metrics. No Leduc policy is presented as a Hold'em opponent.

`poker_cpu/solver_interface.py` preserves the older `SolverRequest`/`SolverAnalysis` research boundary. `TinyRiverCFRBackend` still accepts only an explicit-range first river decision with matching abstract actions and no prior river actions, but now delegates its calculation to the new shared `poker_cpu.solve.solve()` backend. Its time budget remains soft because complete CFR iterations and exact diagnostics are atomic. The older adapter is not the live-table adviser; the table still lacks validated betting-history ranges.

`poker_cpu/river_solver.py` preserves the independently tested complete-board river game and now supplies the shared chance-aware CFR recursion. `WeightedRange` validates and normalizes explicit beliefs, removes public/known-card blockers, and applies per-hand action likelihoods; both game constructors remove mutual private-hand collisions and renormalize joint deals. Synchronous CFR weights regret by opponent/chance reach and average strategy by own/chance reach. CFR+ adds positive regret clipping and linear averaging; DCFR discounts positive/negative cumulative regrets with α=1.5, β=0, γ=2. These are local synchronous variants, with no alternating-update claim. Chance nodes multiply reach by the exact public-card probability before child regrets and average strategies accumulate. Exact best response groups compatible hidden deals by information set. `analyze_root()` reports each acting hand's mixed policy, conditional chip EV for every root action, range-averaged action EV, and NashConv. Conditional action EV conditions on the acting hand and compatible opposing hands, forces a root action, and follows the average continuation policy. It is distinct from reach-weighted counterfactual regret values. `RiverCFR` can start at a replayed nonterminal decision after earlier abstract actions. Safe re-solving remains unimplemented.

`experiments/river_value.py` samples distinct boards and private ranges, solves each river game more deeply, and records a per-hand conditional root EV label. The base network input is a 425-float vector: board and own-hand card indicators, three weighted hand slots for each range, seat, pot, and stack. One experiment appends exact showdown equity, producing 426 inputs. Output is one scalar root EV per own hand. This is not a continuation-value network: it lacks a non-root public betting state and opponent counterfactual-value constraints, so it is not usable as a depth-cutoff oracle or live action adviser. The label audit and suit-augmentation experiment are in `experiments/diagnose_river_value.py`; current measurements are in `docs/BENCHMARKS.md`.

The trainer's default **Play & Learn** mode contains the live game. `request_from_game()` builds a typed request from its public state, action history, visible hero hand, pot, and stacks without reading the opponent's private cards. It calls the same `solve()` API as Solver Lab, but receives `unsupported` because no validated live range model exists; the UI displays the reason instead of EVs. **Solver Lab** is an advanced manual mode. `trainer/static/ranges.js` renders a 13×13 editable range matrix and a separate 13×13 strategy-frequency view over every compatible acting hand. `POST /api/solve` accepts supplied river or tiny turn ranges, board, pot before that street, stacks, iteration budget, first actor, selected earlier abstract actions, and an optional chip NashConv stop target. `/api/river-analysis` remains a compatible alias. Both call `solve()`. The response contains per-hand and aggregate frequencies, conditional EVs and action gaps in chips and BB, exact restricted-game NashConv checkpoints, target status, and latency. A target-met status only applies to the supplied finite abstract game; measured NashConv may move non-monotonically across checkpoints. Flop and preflop remain unavailable in the UI. No opponent counterfactual-value constraint or full-game GTO guarantee is claimed.

`poker_cpu/ranges.py` supplies illustrative presets and canonical suit-combo expansion, including one-combo turn mechanics examples. Button-open and big-blind-defense class frequencies are explicit design assumptions at 100 BB; they were not learned or solved. They expand to hundreds of combos and must be narrowed to the current eight-combo-per-player lab input limit. `poker_cpu/range_inference.py` replays public `HoldemGame.events`, removes newly public cards, conditions a known hero hand without seeing opponent cards, and applies a required hand-specific action-likelihood callback by Bayes' rule. It labels every result unvalidated for live analysis because no fitted/calibrated likelihood provider exists. `poker_cpu/public_chance.py` remains an independent check on reveal probabilities and blockers. The multi-street tree now traverses exact public chance itself, but root action quality still needs broader position and deeper-reference validation before earlier-street recommendations are useful.

`poker_cpu/one_street_solver.py` adds a separate restricted flop/turn reference. It reuses the river action tree and CFR+ update logic for betting on the current street, but precomputes exact showdown win/loss/tie probabilities by enumerating every remaining public runout for each compatible private deal. Terminal chip payoffs use those probabilities and the already-paid current-street bets. Its explicit continuation rule is **no betting on later streets**. This supplies a testable one-street baseline and validates card-removal/payoff arithmetic; it is not a full turn/flop re-solver, neural cutoff, or opponent-CFV-constrained DeepStack search. Preflop exact runout enumeration is not implemented, and this reference is not connected to the app's advice display.

`poker_cpu/multi_street.py` stores the street, board, acting seat, current-street payments, cumulative payments from the root street, public action/reveal history, raise size, and chance/terminal status in immutable states. It uses the same restricted min/fractional-pot/all-in targets and effective-stack cap as the river reference. Closing a nonriver round yields an exact blocker-aware chance node; the next betting round begins with the big blind, and river showdown uses the existing seven-card evaluator. On the saved four-deal river fixture, 50-iteration frequencies, conditional EVs, and NashConv matched the preserved river implementation to reported precision. Turn-to-river CFR has tests and a one-deal variant benchmark. Exact flop traversal is computationally poor and remains disabled in the UI; preflop has no blueprint. Arbitrary real-game wager histories outside the abstraction return unsupported.

The Hold'em NFSP model was trained using this same engine, 20-chip stacks, 1/2 blinds, the same 525-float observation encoder, restricted preset action mapping, and net-chip rewards divided by 20. It is an experimental policy for that environment; arbitrary human wagers can create observations outside its training distribution. It is separate from Kuhn/Leduc NFSP and from CFR. A true continuation model `(public position, both ranges, hand)` → counterfactual value vector, depth-cutoff integration, validated automatic range inference, and safe continual re-solving remain planned. CPU output is the correctness reference for later acceleration.

The Play & Learn study button copies the current hero decision's public board, pot before the street, stack budgets, own hand, acting order, and current-street actions into Solver Lab. It never copies hidden opponent cards or treats the lab's assumed ranges as inferred beliefs. If the played wager sequence is outside the abstract tree, the lab reports that restriction and requires manual adjustment.

The multi-street CPU game now caches seven-card rank by canonical public board/private hand, so histories that reach the same holding share evaluation. An all-in chance node integrates the remaining cards exactly as unordered combinations and returns the expected chip payoff directly; CFR updates, profile EV, and exact best response all use that same terminal value. Game-state caches are bounded per game and can be collected when the solve ends. The optional `SolverConfig.chance_sampling` path samples public chance during vanilla CFR training with a reproducible seed, while root EV and NashConv still enumerate exact chance. Its result is marked `research_sampled_*`; measured sampled strategies did not pass the fixed-position quality comparison and this path is not exposed by the trainer API. Exact flop and turn search remain limited by range/action-tree size.

The one-click **Solver Demo** is a fixed single river decision inside Play & Learn. `trainer/demo.py` owns the explicit public position and two assumed weighted ranges. `POST /api/demo-analysis` invokes `analyze_river_position()`, which constructs the same typed `SolveRequest` and calls `poker_cpu.solve.solve()` as Solver Lab. The response includes every compatible acting hand's strategy and conditional action EVs, plus exact finite-game NashConv and measured latency. The browser stores that one response and recomputes only the selected-action presentation when the user changes an action; it does not rerun CFR. `trainer/static/ranges.js` draws the same 13×13 strategy matrix used by Solver Lab. The demo does not mutate `TableSession` or read an opponent's actual private cards, so leaving it restores the ongoing normal game. A Chrome test compares rendered frequencies and EVs directly with the live HTTP response.

`TableSession` also captures each actual human decision's typed public `SolveRequest` before applying the chosen action. It stores a public summary and chosen action in the hand's solver-review record, omitting opponent cards. The optional `POST /api/review-decision` route uses that saved request with `use_context="experimental_live"`, the observed hero hand, and three blocker-filtered illustrative opponent combinations; it calls the same `solve()` function. The assumed opponent range is intentionally **not** updated from betting history, so the report is labeled experimental. Supported postflop decisions within the restricted bet tree can yield a report; preflop and arbitrary unsupported wager histories return explicit reasons. Search runs outside the session lock and the result is saved back into the relevant hand record. Default live advice remains gated on validated range inference and broader solver-quality tests.

The post-action review now also accepts supported flop and turn decisions. `SolverConfig.continuation_mode="showdown_cutoff"` routes them through the preserved `OneStreetGame` and the same shared `RiverCFR` updates and `SolveResult` contract. That game solves current-street betting with exact public-card runouts and **no later betting**; its NashConv is exact only within this simplified cutoff game. River review keeps the full restricted `MultiStreetGame`. Preflop is still unsupported. Structured logs are opt-in with `POKER_SOLVER_DEBUG=1`; they contain public decision state, assumed ranges, status, action values, and timing, without opponent hole cards. See [the full pipeline diagnosis](LIVE_SOLVER_DIAGNOSIS.md) for the measured blockers.
