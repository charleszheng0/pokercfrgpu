# Live CFR feedback: code-level diagnosis (2026-10-14)

## Reproduce the trace

Run `POKER_SOLVER_DEBUG=1 python3 -m experiments.live_pipeline_diagnosis 2> experiments/live_pipeline_debug.jsonl`. The [raw request/result trace](../experiments/live_pipeline_diagnosis.json) uses `HoldemGame(button=0, seed=29)`, 100-chip stacks, 1/2 blinds, a passive check/call opponent, and human calls/checks. Structured JSONL logs contain captured decisions, review requests, assumed ranges, solver outputs, timing, and unsupported reasons. They never include the opponent's private cards. The trace is one position per street, not a coverage or quality distribution.

## Exact pipeline

1. `poker_cpu/engine.py:HoldemGame.observe(0)` returns the human's own hand and public state. `trainer/server.py:TableSession._act()` captures a typed request **before** stepping the engine and saves its public summary in `solver_reviews`; `_step()` and `_run_opponent()` complete the action sequence.
2. `poker_cpu/solve.py:request_from_game()` sets board/street, pot before the current street, stack budgets at street start, button/first actor/current actor, current-street action history, street payments, public history, and the hero's visible hand. It deliberately sets `ranges=None`, `range_source="unvalidated_inference"`, and `use_context="live"`.
3. `trainer/server.py:live_analysis_availability()` calls `solve(request)` for the default `solver_feedback` state. `poker_cpu/solve.py:solve()` returns `unsupported` before tree construction when live ranges are not validated. `trainer/static/index.html:render()` displays that reason in `#ev-box`. Its separate NFSP frequency list is **not** CFR advice.
4. Opt-in post-action review calls `trainer/server.py:TableSession.review_decision()` through `Handler.do_POST('/api/review-decision')`. `experimental_review_ranges()` sets the observed hero hand to weight 1 and selects three equally weighted, blocker-compatible example opponent combinations. These weights are **not** conditioned on public betting. `solve()` then runs `RiverCFR` on either `MultiStreetGame` (river) or the existing `OneStreetGame` current-street cutoff (flop/turn). `serialize_experimental_review()` sends frequencies, conditional chip/BB EV, selected-action loss, NashConv, iterations, latency, and assumptions. `trainer/static/index.html:renderSolverReviews()` displays the response; the browser test compares rendered values with the HTTP body.

## Observed hand and failure points

| Street / human choice | Public input to `SolveRequest` | Default live path | Assumed-range full-tree path | Opt-in cutoff/review path |
|---|---|---|---|---|
| Preflop / call | Board empty; hero `8s Qc`; pot before street 0; start stacks 100/100; paid blinds 1/2; button acts first | `unsupported`: `solve()` returns before range check because no preflop game/blueprint exists | Same immediate unsupported result, 0 iterations | Review says unsupported; no fabricated EV |
| Flop / check after opponent check | `5s 4h Js`; pot 4; stacks 98/98; one prior check | `unsupported`: missing validated betting-history ranges | Three compatible deals exceed the full-tree exact-flop cap of one deal; 0 iterations | Existing one-street CFR+ cutoff, 500 iterations, **1,532.0 ms**, **0.0003649-chip NashConv inside the cutoff game** |
| Turn / check after opponent check | `5s 4h Js Qh`; pot 4; stacks 98/98; one prior check | `unsupported`: missing validated ranges | Full turn→river tree did run, but **one iteration took 13,454.3 ms** and left **43.5924-chip restricted NashConv** | One-street CFR+ cutoff, 500 iterations, **466.7 ms**, **0.0002181-chip NashConv inside the cutoff game** |
| River / check after opponent check | `5s 4h Js Qh 2s`; pot 4; stacks 98/98; one prior check | `unsupported`: missing validated ranges | Multi-street river CFR+ with assumed ranges, 1,000 iterations, **850.3 ms**, **0.00007175-chip restricted NashConv** | Same river calculation is exposed in post-action review |

All four positions use hero `8s Qc`. The fixed opponent range after blockers is `Ac Ad`, `Kd Kh`, `9h 9s`, each at one-third weight. The normal engine legal actions on flop/turn/river were check, bet-to-2, bet-to-4, and bet-to-98; the restricted cutoff and river reports contained those same actions. Example calculated cutoff values: flop check frequency 99.9976% and conditional EV −0.7852 BB; turn check frequency 99.9986% and conditional EV −0.2121 BB. These numbers are entirely conditional on the illustrative range and **no further betting after the analyzed flop or turn**. They are not full-game EV or GTO frequencies.

## Root causes and smallest changes

| Failure category | Root cause in code | Smallest honest change |
|---|---|---|
| Missing functionality: preflop | `solve()` explicitly returns unsupported for preflop. `MultiStreetGame` accepts only 3–5 public cards and starts postflop with no blinds/BB option. | Add a separately tested preflop betting state with blinds, button-first order, BB option, chance/cutoff model, and bounded payoffs; compare against engine action/payoff fixtures before exposing any value. A UI button alone cannot fix this. |
| Incorrect/missing ranges on every street | `request_from_game()` has no opponent posterior; `live_analysis_availability()` sends `ranges=None`. `range_inference.py` requires an action-likelihood callback, but no calibrated provider exists. | For an **opt-in experiment**, supply a disclosed prior and label it unconditioned (done for post-action review). For default live advice, fit and validate initial priors and action likelihoods, replay board/action events, and quantify posterior sensitivity and calibration. |
| Unsupported flop full-tree states | `solve()` caps exact flop at one compatible deal/three iterations and disables ordinary app use. Three-deal live trace fails before traversal. | The existing exact-showdown one-street reference can serve a clearly labeled bounded cutoff game (now wired). Full flop-to-river advice needs a validated continuation evaluator or a statistically sound sampled method, followed by action-EV/regret comparisons. |
| Excessive turn latency and inaccurate values | Full `RiverCFR.step()` recursively traverses future river cards and betting branches. At 98-chip stacks, one turn iteration took 13.45 s and NashConv was 43.59 chips. A soft time budget cannot interrupt an atomic iteration. | Use a bounded current-street cutoff (now available experimentally), then replace its no-future-betting terminal values only after a deeper-label/value-model comparison shows better root decisions per second. |
| River default feedback unavailable | The river solver works, but default `use_context="live"` rejects unvalidated/missing ranges. Prior actions must be representable in the restricted tree; arbitrary custom wagers and asymmetric street-start stacks can remain unsupported. | Expose only opt-in assumed-range review for supported river decisions (already done). A calibrated range pipeline and broader wager abstraction are needed before default live advice. |
| API/UI integration | Before this fix, `renderSolverReviews()` offered a solve button only for river, even though the saved typed requests existed on flop and turn. | Route flop/turn reviews through the shared `solve()` cutoff mode and show the response with its no-later-betting label (done). The Chrome test verifies actual displayed EV/frequency values from the API. |

The low cutoff-game NashConv values measure regret only under **fixed exact showdown equity and no later betting**. They say nothing about error against a full turn/flop strategy. The old neural root-value model is not used as a continuation oracle. The next quality gate is a held-out suite comparing cutoff root action EVs and chosen-action regret with deeper multi-street references at tractable stacks/ranges, plus runtime distributions. Preflop remains unsupported; default live advice remains unavailable until range inference is validated. No CUDA measurements were made.
